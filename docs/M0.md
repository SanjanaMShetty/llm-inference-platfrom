# M0 verification

How to prove M0 is done. Every step says what you should see. Record the numbers
you get; they go into `experiments/m0-fakebackend-validation/README.md`.

## Prerequisites

Go 1.23 or newer, Docker, `kind`, `kubectl`, `make`, `curl`. Optional locally:
`golangci-lint` (CI runs it regardless).

## 0. First-time setup

This code was written without a Go compiler available, so the first run is also its
first compile. Expect to fix a typo or two, and run these first:

```bash
gofmt -w .          # normalizes formatting (CI fails on unformatted files)
go vet ./...        # catches compile errors early
```

If you want the module path to match your GitHub repo, rename it once:

```bash
go mod edit -module github.com/<you>/<repo>
grep -rl 'llm-platform/internal' . --include='*.go' | xargs sed -i.bak 's#llm-platform/internal#github.com/<you>/<repo>/internal#g'
find . -name '*.bak' -delete
```

## 1. Unit tests (race detector on)

```bash
make test
```

Expect `ok  llm-platform/internal/fakebackend`. The tests cover streaming format,
`[DONE]` termination, first-token delay, usage chunk, non-streaming responses,
bad-request handling, queue gauges, client-disconnect slot release, and
mid-stream failure injection.

## 2. Static checks

```bash
make fmt-check && make vet
make lint            # needs golangci-lint v2; if your config errors, run: golangci-lint config verify
```

## 3. Run the fake backend and look at the raw protocol

```bash
make build
./bin/fakebackend            # terminal A
```

In terminal B:

```bash
curl -s localhost:8000/healthz                      # ok
curl -s localhost:8000/v1/models                    # lists fake-llm

# -N turns off curl buffering: you should see events arrive one by one,
# after a ~500ms pause, then roughly every 20ms.
curl -N localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"fake-llm","stream":true,"max_tokens":8,"stream_options":{"include_usage":true},"messages":[{"role":"user","content":"hi"}]}'
```

Expect: a role chunk, 8 content chunks (`tok0 ` … `tok7 `), a chunk with
`"finish_reason":"stop"`, a usage chunk, then `data: [DONE]`.

Try it without `-N` to see what buffering does to a stream (everything arrives at
the end). That is the flushing lesson from the SSE discussion.

## 4. Validate the test double (the key M0 measurement)

```bash
./bin/ttftprobe -url http://localhost:8000 -n 5 -expect-ttft 500ms -expect-rate 50
```

Expect `PASS` lines for median TTFT (about 500 to 520ms) and median rate (about
49 to 50 tokens/s), and exit code 0 (`echo $?`). Then break it on purpose to make
sure the check is real:

```bash
./bin/ttftprobe -url http://localhost:8000 -n 3 -expect-ttft 100ms     # should FAIL, exit 1
```

## 5. Failure injection and disconnects

```bash
# Truncated stream: connection drops after 3 tokens, no [DONE]. curl should report an error.
curl -N localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' -H 'X-Fake-Fail-After-Tokens: 3' \
  -d '{"stream":true,"max_tokens":20,"messages":[{"role":"user","content":"hi"}]}'

# Disconnect: start a long stream, press Ctrl-C after a second, then check metrics.
curl -N localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"stream":true,"max_tokens":2000,"messages":[{"role":"user","content":"hi"}]}'
curl -s localhost:8000/metrics | grep -E 'num_requests_running|client_disconnects_total'
```

Expect `vllm:num_requests_running 0` (the slot was released) and
`fakebackend_client_disconnects_total` increased by 1.

## 6. Queue gauges

```bash
watch -n 0.5 "curl -s localhost:8000/metrics | grep -E 'num_requests|cache_usage'"   # terminal B
./bin/ttftprobe -url http://localhost:8000 -n 40 -c 20                                 # terminal C
```

Expect `vllm:num_requests_running` to sit at 8 and `vllm:num_requests_waiting` to
rise above 0 (up to about 12), then both fall back to 0.

## 7. Kubernetes

```bash
time make cluster        # record this duration
kubectl --context kind-llm-platform get nodes     # 2 nodes Ready
make deploy
make smoke
```

Expect the smoke test to print `ok` lines and finish with `SMOKE OK`, including
the same `ttftprobe` PASS checks, now through a port-forward to the cluster.

Pod hygiene check:

```bash
kubectl --context kind-llm-platform -n llm-platform get pods
kubectl --context kind-llm-platform -n llm-platform logs deploy/fakebackend | tail
```

## 8. Clean teardown

```bash
make clean
kind get clusters        # llm-platform must be gone
```

Then run `make cluster` again to confirm it recreates from nothing.

## 9. CI

Push to GitHub and open the Actions tab.

- The `lint`, `test` and `build` jobs should all be green.
- Prove the checks are real: on a branch, add a badly formatted line (for
  example, remove the indentation of one statement), push, and confirm the
  `gofmt` step fails. Revert it.
- If an action or golangci-lint version is rejected, check the current version of
  each in its repository and update `.github/workflows/ci.yml`.

## 10. Record evidence

```bash
hack/capture-env.sh > experiments/m0-fakebackend-validation/environment.txt
```

Fill in `experiments/m0-fakebackend-validation/README.md` with your measured numbers,
save raw probe output under `raw/`, and update `CLAIMS.md` rows C-001 to C-003 from
`planned` to `measured`.

## Done when

| M0 acceptance criterion | Proved by |
|---|---|
| `make cluster` builds a cluster from nothing; `make clean` removes it | Steps 7 and 8 |
| CI is green on a real test suite | Step 9 |
| The fake backend runs locally and as a container image in the cluster | Steps 3 and 7 |
| Configured delay and rate match measured values | Step 4 and the experiment README |
| Time for `make cluster` recorded | Step 7 |
